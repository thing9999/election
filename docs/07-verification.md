# 07. 검증과 실측

## 세 개의 명령

DB(`npm run db`) 말고는 **아무것도 미리 띄워둘 필요가 없습니다.**
API 빌드·기동·시드·정리까지 스크립트가 합니다.

```bash
npm run check             # 검증 8종 전부 (208개 항목)
npm run test:e2e          # E2E 만
npm run test:ui           # 브라우저를 띄워서 눈으로 — 투표 전 과정
npm run test:ui:identity  # 브라우저 — 본인확인 (대리투표 차단까지)
```

| | 항목 | 무엇을 확인하나 |
|---|---|---|
| `privilege:check` | 19 | 앱 DB 계정이 표·로그·체크포인트를 못 고치는가 |
| `crypto:check` | 20 | 봉인 규격 + 개표키 분산(Shamir) |
| `tamper:check` | 16 | 무결성 사슬이 조작을 실제로 잡는가 |
| `identity:check` | 30 | 본인확인 · 완료 문자 · 명부 확정 · 감사 반출 |
| `e2e` | 66 | 로그인부터 개표까지 전 과정 + 익명성 |
| `admin:check` | 24 | 관리자 화면이 쓰는 API 전부 |
| `audit:check` | 3 | 반출본 사슬 + DB 에서 지워진 로그 탐지 |
| `chain:check` | 30 | 블록체인에 보내는 트랜잭션이 맞는가 |

합계 **208개**. 여기에 브라우저 테스트 2개가 별도로 있습니다.

### 왜 오케스트레이터를 두었나

세 가지가 반복해서 발목을 잡았습니다.

**① 쓰로틀.** E2E는 유권자 40명을 연속 인증하므로 운영 쓰로틀(IP당 분당 30회)에서
반드시 429가 납니다. 그때마다 손으로 환경변수를 붙이면 **언젠가 그 값이 운영으로
새어 들어갑니다.** 그래서 검증용 프로세스에서만 완화하고,
`E2E_RELAXED_THROTTLE=1`이 켜진 채 `NODE_ENV=production`이면 **부팅을 거부**합니다.

**② 좀비 프로세스.** `nest start --watch`는 자식 프로세스를 하나 더 띄워서,
부모만 죽이면 포트 4000을 잡은 좀비가 남습니다. 실제로 이것 때문에 테스트 결과가
한 번 못 믿을 상태가 됐었습니다. 그래서 빌드 후 **단일 프로세스**로 띄우고,
정리할 때 프로세스 트리째 죽인 뒤 포트가 비었는지 확인합니다.

**③ 시드 누락.** 안 하고 돌리면 "유권자를 찾을 수 없다"로 죽는데 원인이 안 보입니다.
매번 새로 시드합니다.

사전 점검도 여기서 합니다 — `.env` 존재, 비밀값이 예제 그대로가 아닌지,
DB 연결, 스키마 적용 여부, DB 계정 분리 여부, 포트 점유. 각각 **무엇을 하라는
안내와 함께** 멈춥니다.

## 브라우저로 보는 검증 (`npm run test:ui`)

[e2e/vote.spec.ts](../e2e/vote.spec.ts) — Playwright. **일부러 headless가 아닙니다.**

HTTP로만 두드리는 `scripts/e2e.ts`는 화면이 실제로 그렇게 동작하는지 증명하지
못합니다. 특히 **봉인은 브라우저에서 일어나므로**, 진짜 브라우저에서 진짜 Web Crypto로
돌아가는 걸 한 번은 봐야 합니다.

유권자 한 명의 전 과정을 창을 띄워 천천히 진행하면서, 화면 뒤에서 이걸 확인합니다:

- 인증 **전에는** 이름이 화면에 없다 (명부가 새어나가면 안 됨)
- 인증 **후에는** 마스킹된 이름이 나온다
- `/api/vote`로 실제로 나간 요청 본문에 **후보 이름이 평문으로 없다**
- 나간 필드가 `sealedVote` **하나뿐**이다
- 그 값이 base64 디코딩하면 **정확히 133바이트**다
- 확인번호 8자리에 후보 정보가 없다

```
서버로 나간 것: 133바이트
04127659487c4b2f7ce2cefaf8f73c140720e5e7436e23fca231e1322652da7e…
투표 확인번호: FYG7D24L
```

### 블록체인 고정 (`npm run chain:check`)

**진짜 체인 없이 돕니다.** Besu 나 이더리움이 잘 도는지는 우리가 테스트할 일이 아니고,
**우리가 만들어 보내는 트랜잭션이 맞는지**가 확인 대상입니다.

가짜 JSON-RPC 노드를 세우고, 받은 서명 트랜잭션을 [ethers 로 실제 해독](../apps/api/scripts/fake-chain.ts)해서
우리 지갑이 서명했는지 · 체크포인트 해시가 그대로 실렸는지 · 0원인지 · 되읽어 대조가 되는지를 봅니다.
막아야 할 것(다른 체인 연결, 잔액 0, 되돌려진 트랜잭션, 운영에서의 개발용 키)도 함께 확인합니다.

실제 체인 연동은 테스트넷에서 한 번 더 확인해야 합니다 — 이 검증이 대신해 주지 않습니다.

### 본인확인 경로 (`npm run test:ui:identity`)

[e2e/identity.spec.ts](../e2e/identity.spec.ts) — 서버를 `IDENTITY_VERIFICATION=optional`로
띄우고 두 가지를 화면에서 확인합니다:

- 번호·생년월일은 맞는데 **이름이 다르면 거부**되고 투표 화면으로 넘어가지 않는다
  (= 가족·직원 대리투표 차단)
- 본인이면 **OTP 없이** 바로 투표 화면으로 가서 제출까지 된다

`CI=1`이면 headless로 돌고 실패 시 영상·트레이스를 남깁니다.

### 봉인 검증 (`crypto:check`)

- 봉인 결과가 정확히 133바이트
- 같은 후보를 찍은 표 100장의 암호문이 전부 다름
- 선택과 기권의 길이가 같음
- 다른 선거 공개키로는 열리지 않음
- 1바이트만 바꿔도 개봉 실패 (AES-GCM 인증)
- 봉인 1,351건/초 · 개봉 5,141건/초

### 조작 탐지 (`tamper:check`)

DB를 직접 고쳐 공격자를 흉내내고, 검증이 **실패로 뒤집히는지**를 봅니다.
"통과했다"만 확인하는 검증은 아무것도 증명하지 못하기 때문입니다.
상세는 [04 문서](04-integrity-chain.md).

### 전 과정 (`e2e`)

익명성 검증이 여기 들어 있습니다:

- `information_schema` 조회로 `Ballot`에 `voterId` 계열 컬럼이 **존재하지 않음**을 확인
- `GROUP BY sealedVote` 최대 그룹 크기가 1
- `Ballot.castAtHour`가 전부 정시(분·초가 0)
- 감사 로그의 `VOTER` 액션에 `actorRef`가 하나도 없음
- `Election` 테이블에 개인키 컬럼이 없음

### 동시성

500건 동시 투표 → **성공 500 · 중복 0 · 유실 0**, `hasVoted` 수와 실제 표 수 일치.
같은 유권자로 8건 동시 발사 → **정확히 1건만 성공.**

## 실측치

로컬 1대(개발용 노트북, API·DB 같은 머신, 단일 노드), 유권자 1만 명 명부:

| 구간 | 처리량 | 지연 |
|---|---|---|
| 인증 (OTP 발송+검증) | **42.3 건/초** | — |
| 투표 (500건 동시 발사) | **546 표/초** | p50 716ms · p99 869ms |
| 봉인 (브라우저) | 1,351 건/초 | — |
| 개봉 (개표) | 5,141 건/초 | — |

**투표 경로는 병목이 아닙니다. 인증이 투표보다 13배 느립니다.**

인증이 느린 이유는 argon2 해싱이고 이건 의도된 비용입니다. 다만 라이브러리 기본값
(64MiB·t=3·p=4)은 수년간 유지되는 비밀번호 기준이라 3분 만료 OTP에는 과합니다.
OWASP argon2id 최소 권장치(19MiB·t=2·p=1)로 낮춰 **13.8 → 42.3건/초**로 올렸습니다.

1만 명 기준 용량:

- 42.3건/초 → 1만 명 인증에 순수 CPU 시간 약 **4분**
- 최악을 가정해 2,000명이 마감 직전 5분에 몰려도 **6.7건/초** — 여유 6배
- API는 상태가 없으므로 부족하면 인스턴스만 늘리면 됩니다

재현:

```bash
VOTER_COUNT=10000 npm run seed --workspace=apps/api
LOAD_N=500 npm run load --workspace=apps/api
```

> **주의:** 단일 노트북 수치이고 네트워크 지연이 없습니다. 실제 배포 구성에서 반드시
> 다시 재세요. 특히 **SMS 게이트웨이 응답 시간이 여기 안 들어가 있습니다.**

## 검증하다 발견한 실제 문제들

검증이 잡아낸 것들입니다. 기록으로 남겨둡니다.

| 발견 | 대응 |
|---|---|
| E2E에서 429가 터짐 | IP 기준 레이트 리밋이 **공용 NAT(병원 의국)에서 무고한 회원을 막는** 실제 문제였습니다. `THROTTLE_*`를 환경변수로 빼고 OTP 요청 기본값을 5 → 30으로 |
| 인증 13.8건/초 | argon2 기본값이 병목. OWASP 최소 권장치로 → 42.3건/초 |
| 타입 검사는 통과하는데 서버가 죽음 | `AdminModule`에 `JwtModule` 누락. **DI 배선은 타입 검사가 못 잡는 종류의 버그**입니다 |
| 동시 실행 시 OTP 파일 깨짐 | mock SMS가 JSON 파일 하나를 공유. 전화번호별 파일로 분리 |
| 연속 실행 시 TOTP 거부 | 재사용 차단이 제대로 동작한 것. 테스트가 다음 시간 슬롯을 기다리도록 수정 |
